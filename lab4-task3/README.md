# lab4-task3: Домашние электроприборы

## Условие

Построить иерархию приборов, включить часть в розетку, подсчитать суммарную мощность, отсортировать по мощности и найти по диапазону параметров.

## Решение

Пакеты model, creator, io, service. Heater добавляет температуру, Refrigerator — объём, WashingMachine — загрузку. Бизнес-логика вынесена в ApplianceService.

## Запуск из корня JavaLabs

```sh
mvn -q -pl lab4-task3 compile exec:java
```

## Ожидаемый результат

При стандартном файле суммарная мощность включённых приборов: 2150 Вт. Корректных приборов — 4. Некорректные строки пропускаются.

## Тесты

```sh
mvn -pl lab4-task3 verify
```

## Создание объектов и паттерны

- `ApplianceCreator.create` содержит общие шаги создания прибора: разбор общих полей и подключение к розетке.
- `createAppliance` — Factory Method; переопределён в `HeaterCreator`, `RefrigeratorCreator`, `WashingMachineCreator`.
- `ApplianceFactory` выбирает подходящий Creator по типу записи.
- `HomeCreator` собирает агрегат квартиры из списка приборов (GRASP Creator).
- `ApplianceService` считает мощность, сортирует реализацией Comparator и выполняет поиск. Классы-сущности не содержат поиска или сортировки.

## Файл исходных данных

По умолчанию читается `src/main/resources/appliances.txt` из classpath. Формат:

```text
type;id;name;powerWatts;voltage;pluggedIn;specificParameter
HEATER;H1;Обогреватель;2000;230;true;24
FRIDGE;F1;Холодильник;150;220;true;300
WASHER;W1;Стиральная машина;1800;230;false;7.5
```

Первая строка выше объясняет поля; в реальном файле заголовок должен начинаться с `#`. Поддерживаются пустые строки и комментарии `#`.

Параметр `specificParameter`: температура для обогревателя (5–35 °C), объём холодильника (>0 л), загрузка стиральной машины (>0 кг). Неправильные числа, неизвестные типы, повторы ID, пустые имена, неверные флаги и недопустимые значения игнорируются и логируются. Это выбранная из условия стратегия **игнорирования**, а не подстановки значений.

Собственный файл, например:

```sh
mvn -q -pl lab4-task3 compile exec:java -Dexec.args="lab4-task3/src/main/resources/appliances.txt"
```

## Логирование

Log4j2 настроен в `src/main/resources/log4j2.xml`:

- консоль: DEBUG — голубой, INFO — зелёный, WARN — жёлтый, ERROR — красный;
- `logs/application.log` — все уровни от DEBUG;
- `logs/warnings.log` — WARN и выше;
- `logs/errors.log` — ERROR и выше;
- ротация ежедневно или при достижении 1 МБ; архивы `.log.gz` в `logs/archive`;
- для каждого архивного шаблона сохраняется до 7 индексных архивов в пределах даты. Это не глобальный лимит хранения за все даты.

Папка `logs` создаётся относительно рабочего каталога процесса. В терминале без поддержки ANSI цвета могут не отображаться; в IntelliJ следует включить поддержку ANSI. Три текущих файла создаются автоматически при инициализации логирования.

## Полное покрытие

`mvn verify` проверяет порог JaCoCo **100% строк и ветвей**. Тесты покрывают модели, наследников, фабрики, создание квартиры, успешное и ошибочное чтение, повторные ID, расчёт мощности, сортировку, границы поиска и точку входа.
